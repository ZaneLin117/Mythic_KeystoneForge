# 第二阶段：产品独立化与中文体验

## 决策摘要

第二阶段先把稳定的 MDT 路线编辑器改造成一个能独立识别、默认中文、明确本地保存边界的产品。工作品牌暂定为“秘境路线工坊 / Mythic Route Studio”。8 个副本名称采用产品负责人提供的中文映射；NPC 和技能专名继续使用数据源原文，直到取得可信的中文映射。

## 目标用户与任务

- 用户：需要在游戏外规划史诗钥石路线的中文玩家与车队组织者。
- 核心任务：选择副本，建立拉怪组，核对敌方进度，再通过 MDT 字符串在网页和游戏间传递路线。
- 成功结果：用户无需登录即可完成一次路线创建、自动保存、导入和导出，并能理解失败原因及恢复方式。

## 核心旅程

| 阶段 | 用户目标 | 用户操作 | 系统响应 | 反馈 | 风险/阻力 | 成功条件 |
|---|---|---|---|---|---|---|
| 进入 | 确认工具用途 | 打开本地页面 | 加载默认副本与本地路线 | 显示品牌和“本地自动保存” | 误以为必须登录 | 无账号也能进入编辑器 |
| 选路线 | 获得可编辑路线 | 新建、切换或导入路线 | 更新地图、拉怪组和进度 | 当前路线名称持续可见 | 导入字符串损坏 | 中文错误且保留原路线 |
| 编辑 | 规划拉怪顺序 | 点选敌人、增加或排序拉怪组 | 实时更新地图轮廓和进度 | 操作立即反映并本地保存 | 中文长度挤压侧栏 | 核心按钮不重叠、不截断 |
| 导出 | 带回游戏 | 点击“导出 MDT” | 编码并写入剪贴板 | 显示复制成功或失败提示 | 剪贴板权限被拒绝 | 错误可理解，路线不受影响 |
| 恢复 | 继续上次工作 | 刷新或重新打开页面 | 从浏览器存储恢复 | 路线名称与内容一致 | 数据版本变化 | 能回到可用状态或给出恢复路径 |

## P0 范围

- 负责人：Web 客户端。
- 独立品牌标题、代码原生标志与青蓝深色视觉系统。
- 默认中文、中文/英文即时切换及浏览器记忆。
- 路线、导入导出、绘制、搜索、帮助和主要提示文案中文化。
- 8 个副本在中文模式显示中文全称与紧凑短标，英文模式保留上游名称。
- 明确展示“本地自动保存”，旧的默认路线名安全迁移为“未命名路线”。
- 移动端只常驻一个副本入口，避免 8 个图标挤占地图。
- 登录、分享、协作和统计默认关闭；只有配置自有服务并显式设置环境变量后才启用。
- MDT2 导入失败时保留现有路线，并提供分阶段中文错误。

## P1/P2 后续范围

- P1：补齐右键菜单、敌人详情、比较模式、在线协作房间详情等次级界面翻译。
- P1：接入 NPC、技能等其余游戏内容的可信中文名称映射，并提供回退策略。
- P1：完成游戏插件真实导出、网页编辑、重新导入游戏的跨端夹具。
- P1：部署自有分享、身份、协作与排行榜基础设施。
- P2：重新设计地图标记、拉怪组卡片和移动端全屏编辑模式。
- P2：建立正式品牌名称、Logo 资产、域名和视觉资产规范。

## 非目标

- 本阶段不改动敌人计数、路线存储和 MDT 编解码领域规则。
- 不使用 Threechest 的 Firebase、RTC、分析或分享服务作为正式二开后端。
- 不把未经确认的地下城中文译名写入数据层。

## 交互状态

```text
本地进入
  -> 恢复上次路线或创建空路线
  -> 选择副本/路线
  -> 编辑拉怪组
  -> 本地自动保存
  -> 导出 MDT

导入恢复：
无剪贴板权限 -> 打开手动输入 -> 校验 -> 成功替换/另存，或中文报错 -> 返回原路线

在线能力：
默认关闭 -> 配置自有服务与环境变量 -> 显式启用 -> 执行对应端到端验收
```

## 验收标准

- Given 首次打开页面，When 未设置语言，Then 默认显示中文品牌和核心操作。
- Given 用户切换英文，When 刷新页面，Then 语言选择保持且主要界面切换为英文。
- Given 旧默认路线名为 `Default threechest.io`，When 页面加载，Then 只迁移该自动生成名称，不改动其他用户路线名。
- Given 390×844 视口，When 侧栏展开，Then 顶部只显示一个副本入口，核心路线按钮保持可操作。
- Given 剪贴板读取被拒绝，When 点击导入，Then 打开手动输入弹窗且空内容不能确认。
- Given 在线功能变量均未启用，When 页面加载，Then 不显示登录、分享和协作入口，也不装载对应同步组件。
- Given 有效 MDT2 字符串，When 导入，Then 地图和拉怪组更新；Given 损坏字符串，Then 显示中文错误且原路线不变。

## 开放问题

- 正式中文品牌名称和 Logo：产品负责人确认后替换工作品牌。
- NPC 与技能中文专名数据源：数据负责人确认来源、版本和更新频率。
- 分享、账号和协作后端：部署负责人确定自有基础设施后再启用功能开关。
