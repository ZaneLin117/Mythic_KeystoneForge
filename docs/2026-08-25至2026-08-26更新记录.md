## 4. WCL 排行与 GitHub Pages

### 4.1 排行 JSON

- Warcraft Logs 排行结果改为公开 JSON，并与静态网站一起发布到 GitHub Pages。
- 前端通过 `VITE_RANKINGS_BASE_URL` 读取排行快照，不需要在浏览器中保存 WCL Client Secret。
- 同步任务会先下载现有快照，再补充缺失路线，减少重复请求。
- 针对 WCL 限流增加重试与恢复逻辑；若同步未完整成功，不会上传半成品数据。
- GitHub Actions 默认每 6 小时运行一次排行同步，也可以手动执行。
- WCL 凭据仅配置为 GitHub Actions Secrets：
  - `WCL_CLIENT_ID`
  - `WCL_CLIENT_SECRET`

> 安全要求：文档、源码、日志和截图中都不得记录 Secret 的实际值。

### 4.2 GitHub Pages 静态部署

- 新增 `.github/workflows/deploy-pages.yml`。
- 推送到 `main` 后自动执行安装、类型检查、Vite 构建和 Pages 发布。

- 当前线上地址：<https://zanelin117.github.io/Mythic_KeystoneForge/>

- MDT 导入导出、本地路线保存、地图编辑、参考路线、怪物信息和技能说明均可在纯静态环境使用。

## 6. 已知限制与注意事项

1. 构建期间仍会出现 `Could not find spell id 1300666` 提示；当前为非阻塞提示，构建最终成功，但后续应补齐或过滤该技能数据。
2. Vite 会提示部分构建分块超过 500 kB，当前不影响使用，后续可继续拆分首屏和协作模块。
3. GitHub Pages 是境外静态托管，中国大陆网络的访问速度和稳定性会因地区、运营商和网络环境而变化。
4. WCL API 存在请求频率限制；同步任务已重试，但不保证每次都能立即获得全部最新排行。
5. 当前网络路线是人工收集内容，随着 MDT 插件更新可能出现旧怪物实例，需要继续运行完整性测试。
6. 侧栏备注通过地图位置自动关联。如果一条备注放在远离实际波次的位置，它可能关联到空间上最近但语义上并非目标的波次；移动地图备注即可调整归属。
7. GitHub Pages 更新后浏览器可能暂时缓存旧资源，可使用 `Ctrl + F5` 强制刷新。

## 8. 当前使用与发布方式

```powershell
cd D:\project\Wow\mdtpage
corepack yarn@1.22.22 install
corepack yarn@1.22.22 dev
```

本地访问：<http://localhost:5173/>

### 本地验证

```powershell
corepack yarn@1.22.22 lint
corepack yarn@1.22.22 test
$env:VITE_BASE_PATH='/Mythic_KeystoneForge/'

```

```powershell
git add <本次修改的文件>
git commit -m "更新说明"
git push publish main
```

推送成功后，GitHub Actions 会自动构建并更新 GitHub Pages。
